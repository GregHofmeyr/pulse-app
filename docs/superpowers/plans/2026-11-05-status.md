# Status (Online, DND, Invisible, appear offline to them) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One account status (Online / Do Not Disturb / Invisible, DND with timers) and "Appear offline to them" per
person, with true presence never leaving the server for a viewer who shouldn't see it (#45).

**Architecture:** The server computes a per-viewer `PresenceView` (status + last seen) for every (subject, viewer)
pair from one pure function; Ready, `PresenceChanged` and anything else carrying presence go through it, and the hub
remembers what each viewer was told so it only sends changes. Your own status, DND end and hidden list reach only your
own sessions. The client draws every dot / "last seen" from one function (`presenceOf`) and silences alerts with one
check (`dndActive`).

**Tech Stack:** Rust (axum, sqlx/SQLite, tokio), ts-rs bindings, Tauri 2 core, Svelte 5 + vitest.

**Spec:** `docs/superpowers/specs/2026-11-05-status-design.md`

## Global Constraints

- Privacy is enforced on the server, per viewer: no payload or event leaks true presence to a viewer who shouldn't see it.
- Invisible / hidden: viewer sees exactly "offline"; last seen frozen at the moment you stopped appearing online to them;
  when both apply, the earlier moment.
- Decisive actions (messages, typing, voice, streams, soundboard, renames) are untouched.
- DND silences: message sound, desktop notifications, mention pings, the went-live toast and its sound, the
  badge-unlocked sound (toast still shows). Not silenced: in-call sounds; badges/counts keep updating.
- DND timers: 1 hour, 8 hours, until tomorrow morning (08:00 local next day, sent as an absolute time), until I turn it off.
- New protocol fields are `serde(default)`. Migration is 0019. Old `users.status` (CHECK online/dnd) is left unused.
- UI: "Appear offline to them" / "Stop appearing offline to them" is an ordinary item in every person right-click menu,
  never a button or link on a card or under an avatar. Picker opens from your own avatar at the bottom of the sidebar.
  Hidden list in Settings → Privacy.
- Public repo: test people are alex, sam, kim, jo; no real names, IPs, secrets.
- Cargo: `CARGO_BUILD_JOBS=4 flock ~/Projects/pulse-app/target/.cargo-serial nice -n 19 ionice -c3 cargo …`,
  tests `-- --test-threads=4`, worktree's own `target/`.

## Decisions (builder's calls)

- **Storage (0019):** new columns `users.presence TEXT NOT NULL DEFAULT 'online' CHECK (presence IN
  ('online','dnd','invisible'))`, `users.dnd_until TEXT`, `users.invisible_at TEXT`; table
  `presence_hidden(owner_id, target_id, hidden_at, active INTEGER NOT NULL DEFAULT 1, PK(owner_id,target_id))`,
  both FKs `ON DELETE CASCADE`, STRICT. Old `status` column untouched (no table rebuild).
- **Freeze moments never jump:** when you go invisible, `invisible_at` = now if connected, else your real
  `last_seen_at` (else now). When you hide from V, `hidden_at` = the last seen V currently sees if V already sees you
  offline, else now. Unhiding V while you're Invisible keeps the row with `active = 0` (off your list, still V's freeze
  while you stay invisible); going visible clears `invisible_at` and deletes `active = 0` rows.
- **DND expiry:** views treat an expired DND as Online (check on read); a sweeper every 15 s rewrites expired rows to
  online, tells your sessions (`StatusChanged`) and re-syncs presence for others.
- **Hub:** `announced: HashMap<(subject, viewer), PresenceView>`; `sync_presence` and Ready's people run under one
  `tokio::sync::Mutex` so a status change and a connect can't reorder announcements.

## Review Focus

- Hide someone while already invisible, then go visible: their last seen must not jump forward → test
  `hide_while_invisible_then_visible_keeps_freeze`.
- Unhide someone while still invisible: they keep seeing you offline with the same last seen →
  `unhide_while_invisible_stays_frozen`.
- A second device connects while invisible: viewers get no event at all → `second_device_while_invisible_is_silent`.
- DND set with a time in the past or absurdly far out → 400 (`dnd_until_must_be_future_and_bounded`).
- Old clients (no `status` field) still parse Person / PresenceChanged → protocol default test.

- `Event::StatusChanged { user_id, status: OwnStatus }` and
  `Event::AppearOfflineChanged { user_id, target_id, hidden: bool }`, both `only_for(user_id)`, no channel.
