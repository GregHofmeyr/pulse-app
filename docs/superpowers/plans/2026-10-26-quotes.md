# Quotes, quote awards and Quote of the Year: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a `quotes` channel kind where every post is a quote (lines with real speakers, text or image), scored by
one reaction per person, with per-line quote awards, a replies side panel, a leaderboard, plain-name speakers that can
be linked to members, and a live, server-wide Quote of the Year event with a winner card.

**Architecture:** a quote is a `messages` row plus `quotes`/`quote_lines` rows; replies are messages with a
`thread_root_id`, kept out of the main list and every count. New server modules `quotes/` (lines, awards, speaker
links, leaderboard, search) and `qoty/` (event rules, a 10 s end-by-time sweeper that also runs on boot). Reactions
reuse `messages::reactions::toggle` with the existing `one_per_person` mode. The media store gets a second kind
(`quote`). Client core (`api.rs`, `commands.rs`) gains one method/command per route; the Svelte side extends the pure
reducer in `state.ts` and adds focused components.

**Tech Stack:** Rust (axum, sqlx/SQLite, image), ts-rs bindings, Tauri 2 core, Svelte 5 + vitest/jsdom.

**Spec:** `docs/superpowers/specs/2026-10-22-quotes-design.md` (approved 2026-10-22; binding, read it in full),
built on `docs/superpowers/specs/2026-10-22-reactions-emoji-design.md` and its shipped code. Where they disagree,
the **Spec reconciliation** below decides.

## Spec reconciliation

The spec predates the reactions/emoji push. These are the places where the shipped code forces a choice or the spec
is silent. Approved behaviour is unchanged unless an item says otherwise. Items marked **(owner)** were put to the
owner; their answers (2026-10-27) are folded in below and marked **answered**.

1. **Protocol version (owner).** An older client's `Ready` fails to parse once a channel has kind `quotes` (the client
   skips frames it can't parse, so it would hang on "connecting"). Bump `PROTOCOL_VERSION` and `MIN_CLIENT_VERSION`
   to `2`: older builds get the existing "update required" screen. **Answered: yes, force the update.**
2. **Reaction mode is per channel; the spec wants it per quote.** Replies and system cards live in the same channel
   but must keep normal reactions (spec §4.1). `toggle` applies `OnePerPerson` only to a message that is a quote
   (`kind = 'normal' AND thread_root_id IS NULL` in a `quotes` channel). Quotes channels are created with
   `reaction_mode = 'one_per_person'`.
3. **Membership checks match `ChannelKind::Text` only.** `messages::send`, `reactions::toggle` and the voice
   routes (`token` and `voice::routes::may_join`, which also gates every LiveKit join; both refuse only `Text`, so a
   quotes channel would mint voice tokens) all switch to a new `ChannelKind::is_server_chat()` (`Text | Quotes`).
4. **Deleting is a soft delete today** (content blanked, reaction rows kept but hidden). For a quote, the same soft
   delete plus, in one transaction: reaction rows and awards deleted, replies soft-deleted, its QotY options and the
   votes for them removed. `qoty_winners` rows stay (spec §3.2).
5. **`messages.reply_to_id` already exists** (inline "replying to"). The spec's replies are threads: a new
   `thread_root_id`. Posting a plain message into a quotes channel without `thread_root_id` is refused (the main list
   is quotes only); `reply_to_id` inside a thread must point into the same thread.
6. **The media store only makes 128×128 emoji (owner, minor). Answered: image quotes stay animated, like custom
   emoji.** New `MediaKind::Quote` and `process::quote_image`, sharing the emoji pipeline (one decode/frame loop
   with the fit and output cap as parameters, not a copy): same input rules as emoji (2 MB, PNG/JPEG/GIF/WebP,
   ≤ 4096 px a side, 300 frames, same decode alloc and 100 Mpx animation budget). A still input → a still WebP fitted
   within 1600 px on the long side, never enlarged, ≤ 1 MB. An animated input → an **animated** WebP fitted within
   640 px on the long side (never enlarged, frame timing kept), ≤ 4 MB, **plus** its first frame as a still (stored
   like an emoji's `still_hash`). Same upload rate limit (`upload_user`), disk guard and processing slots. Cleanup
   keeps hashes used by `quote_lines` and their stills. The client shows image lines with the same animate/freeze
   rule as custom emoji (`lib/animate.svelte.ts`'s `wireEmoji`: "Animate emoji" setting always/hover/never, focused
   window, on-screen, frozen while live, never under reduced motion), importing it unchanged.
7. **Unread and mentions are per channel and monotonic.** Replies never count as unread (server `reads::states_for`
   and the client reducer). An @mention in a reply plays the mention sound as usual and **counts in the channel's
   mention pill until you open that quote's replies** (a per-user, per-quote seen point clears it). **Answered: yes.**
8. **Which year.** The server only knows UTC. The client sends its local date (`today`, `YYYY-MM-DD`) with a new
   quote; the server keeps it as `posted_on` if within ±1 day of the UTC date, else uses the UTC date. Year =
   `said_on ?? posted_on`. `said_on` stays import-only (no route sets it in this push).
9. **Plain-name speakers are resolved at read time.** Lines keep their raw `speaker_id`/`speaker_name`;
   `speaker_links` joins on a normalised `name_key`. Linking, re-pointing and undoing therefore never touch lines, and
   the original name always survives. "Your own line" means the *effective* speaker. An award whose giver later
   becomes the effective speaker (by a link) is kept but not counted or shown while that link stands.
10. **Linking is not an edit.** Linking/unlinking is allowed while a quote is a live QotY option (the speaker lock in
    §3.2 is about edits); wins snapshot the effective speakers at the end. **Answered: yes.**
11. **Top 5 details.** A quote with a score of 0 is never an automatic option (a quiet year can have fewer than 5;
    adding by hand still works); quotes that already won an earlier year are excluded from the automatic top 5 too
    (the spec says so only for hand-added ones). **Answered: yes.**
12. **Ending without votes "says so"** with a short system line in **every** quotes channel of the server. Co-winner
    cards: one per channel holding a winner (spec). **Answered: yes.**
13. **Reopen and stale cards.** Reopening deletes the event's `qoty_winners` rows and hard-deletes its winner/no-vote
    cards (publishing `MessageDeleted`), so no quote keeps a mark from an ending that was undone. One event row per
    `(server, year)`: start for a year that has any event is refused; reopen reuses the row. **Answered: yes,
    reopening removes the earlier card.**
14. **Votes are public (owner). Answered: show who voted** ("the competition of asking someone why on earth they
    voted for X"). Every `QotyOption` carries `voters: Vec<UserId>` (in vote order) next to `votes`, sent to the
    normal audience (`Audience::Everyone`, as every QotY event). Since votes are public, `QotyEvent.my_vote` and the
    `QotyMyVote` event are dropped: the client derives "my vote" from `voters` containing me. The winner card
    (`QotyCard.voters`, snapshotted into the system payload at the end) and leaderboard winners (`LeaderboardWin.votes`
    / `voters`, from `qoty_votes`) show them too. Awards get the same treatment: `QuoteLine.awarders: Vec<UserId>`
    (counted awarders, oldest first) inline and `QuoteAwardChanged.awarders` (absolute list), replacing the separate
    `GET /quote-lines/{id}/awards` route. The UI shows a compact avatar stack (`VoterStack`: up to 5 avatars then
    "+N", every name in a tooltip) beside each vote count and award count.
15. **Ending by time** is a 10-second sweeper (plus one sweep before the server binds on boot), not per-event timers;
    an event ends within ~10 s of `ends_at`. Every ending is a guarded `UPDATE … WHERE ended_at IS NULL`, so racing
    ends post one card.
16. **Lengths (owner, minor).** "A few hours" = 3 h, "a day" = 24 h, custom = 5 minutes to 14 days, or open until
    ended. Same choices on reopen. **Answered: yes.**
17. **Limits (spec "my call" values kept):** 10 lines, line text ≤ 4000 chars (`MAX_LEN`). Plan's own: caption ≤ 200
    chars, plain name 1-32 chars, leaderboard lists 10 entries, search 20.
18. **`messages.content` for a quote** is a server-written plain rendering (`“text” — speaker` per line; `[image]` for
    image lines) so previews and anything reading `content` keep working. `PATCH /messages/{id}` refuses quotes (400);
    quotes are edited through their own route.
19. **Winner card** is a system message (`messages.kind = 'system'`, existing `system_payload`); `Message` gains a
    typed `qoty_card` parsed from that payload.
20. **"Each entry jumps to the quote" (owner). Answered: build it properly**, reusable later for search, mentions
    and pins. Server: `GET /channels/{id}/messages` gains `around=<id>` (a window: up to `limit/2` older, the target,
    the rest newer; 404 when the target isn't a visible main-list message of that channel) and `after=<id>` (the
    next page newer than an id), both newest first like today and both excluding replies. Client: history gets an
    `end` flag beside `start`; `jumpTo(channelId, messageId)` (`lib/jump.ts`) shows the message if it's loaded,
    otherwise replaces the channel's list with the `around` window (`end: false`); scrolling to the bottom of a
    detached window pages forward with `after` until it reaches the latest; live messages for a detached channel
    still count unread/latest but aren't spliced in (no gap); a "Jump to present" bar returns to the latest. The
    target scrolls into the middle and flashes a highlight (a static outline under reduced motion). A leaderboard
    entry switches to that quote's channel and jumps to it. *As built (Task 15):* the core returns `None` for an
    `around` 404 (`api.listMessagesAround` → `Message[] | null`), so "Couldn't find that message" is told apart
    from a failed request (its error is shown instead); a live message missed by a detached list is noted
    (`history[c].missed`) so paging forward doesn't stop short of it; `ReadStateUpdated` gains an absolute
    `unread` count (a detached list can't count it); a detached window survives a reconnect.
21. **Animations:** no new dependency. CSS keyframes / Web Animations API, off when `motion.reducedMotion`
    (`lib/animate.svelte.ts`) is true.
22. **Server-wide audience.** QotY events have no channel, so `audience_for` sends them to everyone, the
    same audience as server channel events (`Audience::Everyone`); taking part requires server membership
    (`is_server_member`), like posting. "M" = the server's `server_members` count.
23. **Main moved (merged 2026-10-27).** Every new mutating route (quote edit/delete, awards, links, votes, options,
    end, reopen, replies seen) first hits `s.limits.mutate_user` (429), as message edit/delete and reactions now do;
    every route that grows the database (post quote, reply, start) calls `crate::media::writes_ok(&s.cfg)?` as
    `send` does. Migration number 0008 is still the next free one.

## Review Focus

1. **Racing endings** (the sweeper, a boot sweep and someone pressing End at once) → exactly one ending, one set of
   cards. Pinned in Task 10 (`ending_races_post_one_card`).
2. **Deleting the leading quote mid-event** → its option and votes vanish, those voters can vote again, the next end
   never names the deleted quote. Pinned in Task 10 (`deleting_an_option_frees_its_voters`).
3. **Concurrent votes and awards** → final broadcast counts equal the database. Pinned in Tasks 6 and 10
   (`concurrent_awards_end_on_the_true_count`, `concurrent_votes_end_on_the_true_count`).
4. **A plain name later linked to an awarder** → their award on "their own" line stops counting and comes back on
   unlink. Pinned in Task 7 (`self_awards_via_a_link_are_not_counted`).
5. **A broken or oversized image pasted into the composer** → the line shows the server's message and stays editable;
   nothing posts. Pinned in Task 2 (`quote_image_refuses_what_emoji_refuse`) and Task 14
   (`a_rejected_image_keeps_the_line`).
6. **Jumping into a detached window** → live messages never splice in after a gap; paging forward meets the
   latest exactly once (no duplicates, no holes). Pinned in Task 9 (`around_and_after_page_without_gaps`) and Task 15
   (`a live message in a detached window waits for the present`).
