## GIPHY's rules change the spec's search proxy

GIPHY's API docs (developers.giphy.com/docs/api, "Prohibited Integration Practices", read 2026-11-11) say:

- "Do not proxy requests to GIPHY, either API calls or media URL loads. All requests to GIPHY should be made
  directly from the client side (e.g. your app or web browser)."
- "Do not cache API responses or media URLs or cache or store copies of GIPHY's media assets."
- "Do not strip or modify URLs returned by the API", "Do not reorder content or filter out our content", "Do not mix
  GIPHY's content with content from other providers in the same grid".
- Apps must "conspicuously display 'Powered By GIPHY' attribution marks where the API is utilized".
- Every key starts as a beta key: 100 API calls an hour (search `limit` at most 50). A production key needs an
  application and GIPHY then "reach[es] out via email to discuss pricing"; "for most applications a rate limited
  beta key is sufficient".

The spec's server proxy with an in-memory cache (builder's call, not an owner decision) is exactly what the first two
rules forbid, and the spec says to follow GIPHY's terms. So:

- **The server never calls GIPHY.** It keeps `GIPHY_API_KEY` in its environment and hands it (and the rating) only to
  signed-in people (`GET /gifs/config`, rate-limited per person). Without the key the route says so and the picker
  shows "GIFs aren't set up on this server yet".
- **The app's Rust core calls GIPHY directly** (search, trending), never caches the answers, and hands the picker
  GIPHY's own URLs untouched. The key never reaches the webview.
- **Nothing GIPHY serves is stored:** messages and favourites keep the GIF's id, title and size only. Chat draws a GIF
  from GIPHY's public media links for that id (`https://media.giphy.com/media/<id>/…`, the same links GIPHY's own
  "copy GIF link" gives), so a sent GIF and a pasted link render the same way.
- **The link-preview unfurler skips GIPHY links** (it would fetch GIPHY's page server-side and store a thumbnail).
  0.2.x clients therefore see the GIPHY link as a plain link (the spec's "link/embed").
- Analytics pingbacks (onload/onclick/onsent) are "highly recommended", not required: none are sent (no tracking).

## Builder's calls (with why)

- **Rating `pg-13`** by default; `GIPHY_RATING` (g, pg, pg-13, r) overrides it. Sent on every search and trending.
- **A pick sends at once** as its own message (Discord's feel), replying to the message being replied to, if any.
  Whatever is typed in the box stays there.
- **`Message.gif: Option<Gif { id, title, width, height }>`** (absent for everything else), also on
  `SendMessageRequest`. The server checks the content is a GIPHY link to that id (else 400) and the title and sizes
  are sane, and stores it as JSON in a new `messages.gif` column. An edit that changes the link drops the `gif`.
- **Favourites:** `gif_favourites (user_id, gif_id, title, width, height, created_at)`, newest first, at most 200 per
  person. `GET /gifs/favourites`, `POST /gifs/favourites` (a `Gif`, idempotent), `DELETE /gifs/favourites/{id}`
  (idempotent). No gateway event: the picker fetches them when it opens, so they follow you across devices.
- **Rate limit:** `gif_user` (30 at once, one every 2 s) on `/gifs/config` and the favourite writes. The core keeps
  the config for the session, so it asks once. GIPHY's own 100-an-hour beta limit is shared by everyone on the server;
  a 429 shows "GIF search is busy right now. Try again in a minute." The picker searches 350 ms after typing stops.
- **Picker:** the emoji picker's frame (360 × 420, `.picker` look): search field on top, a rail with Trending and
  Favourites (the emoji picker's rail is its tabs), a two-column masonry grid in GIPHY's order, "Powered by GIPHY" in
  the footer where the Twemoji credit sits. Hovering a GIF shows its title in the footer and a star. Load more on
  scroll (24 per page).
- **Chat:** at most 3 GIFs per message (as link previews); a message that is only a GIPHY link shows just the GIF.
  Drawn at GIPHY's fixed-height 200 px rendition (`200.webp`, still `200_s.gif`), at most 300 px wide, alt text =
  title (from the message, or the link's slug for a pasted one, else "GIF"). Plays while the window is focused and the
  GIF is on screen; under reduced motion it shows the still until hovered or clicked (a click toggles it). A star on
  hover adds or removes it from your favourites. One-line previews (reply snippets, notifications, the conversation
  list, pins) say "GIF".
- **CSP:** `https://media.giphy.com https://*.giphy.com` added to `img-src` in every `tauri*.conf.json`.
