# Polls (#157) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a poll is a message with a question, 2–10 options, live votes and a close, in text and voice chats, DMs and
groups.

**Architecture:** the poll is a normal (authored) message whose `content` is a plain-text fallback and whose poll lives
in a `polls` table with its votes in `poll_votes`; the server attaches a per-viewer `Message.poll` on every read. Vote
changes and closes publish a content-free `PollChanged` and each client fetches its own view; a sweep closes due polls
and posts the "ended" system line once.

**Tech Stack:** Rust (axum, sqlx/SQLite, ts-rs), Tauri 2 core, Svelte 5 + vitest.

**Spec:** `docs/superpowers/specs/2026-11-09-polls-design.md`

## Global Constraints

- Question 1–200 characters; 2–10 options of 1–80 characters, distinct (any case); trimmed, one line each.
- Ends in: 1 hour, 1 day (default), 1 week, No end.
- Results: creator always, a voter after voting, everyone once closed; before that rows show no counts.
- Anonymous polls never send voter ids to anyone (counts only); chosen at creation, never changed.
- No notification for a close; the ended line: `📊 alex's poll ended: Valheim won (4 votes)` (+ "See poll" in the
  new client); ties name every tied option.
- Not in quotes or clips channels. No editing a poll after posting.
- Existing tokens only; icon sizes 14 inline / 16 buttons / 18 nav, or the neighbouring composer buttons' 20; the vote
  bar's growth off under reduced motion; motionCss / colorTokens / icon guard tests pass.
- Public repo: test people alex, sam, kim, jo.

## Builder's calls (with why)

- **A poll is an authored message, not a system line**: it replies, reacts, scrolls and is deleted by its author like
  any message (the spec). `kind` stays `normal` so a 0.2.1 client, which knows no other kind, renders it.
- **Fallback text for old clients** in `content`: `📊 Poll: <question>` then one `• <option>` line each, then
  `(Update Pulse to vote)`. A 0.2.1 client ignores the unknown `poll` field and `PollChanged` event (serde ignores
  unknown fields; its gateway skips frames it can't parse), so it shows that text as a message. Search, reply
  snippets, notifications and the DM list preview read it too. The ended line's text reads on old clients as any
  unknown system line does.
- **Per-viewer views by refetch**: events go to everyone in a chat with one payload, but results differ per viewer
  (voted or not, creator). So `MessageCreated` carries the neutral view (no results, no `mine`), `PollChanged {
  channel_id, message_id }` carries nothing secret, and a client that holds the message fetches
  `GET /messages/{id}/poll`. History pages are already per viewer (`attach(db, me, page)`, as quotes do). The client
  keeps a held message's poll on `MessageCreated`/`MessageUpdated` (as pins do), so an event never undoes a fetched
  view; the creator's client fetches once when its own poll arrives.
- **Vote = set my choices**: `PUT /messages/{id}/poll/votes { options: [..] }` replaces your choices (empty removes
  your vote); single choice takes at most one. Idempotent, so a retry or two quick clicks can't toggle twice. Your
  choices are replaced inside one write transaction: "one per voter for single choice" holds without a trigger.
- **Total** shown on the card is the number of people who voted (`voters`), always visible: it reveals no
  distribution. Percentages are of voters (a multi-choice poll's can add up past 100 %). The ended line counts the
  winner's votes.
- **Closing**: `closed_at` is set by `UPDATE … WHERE closed_at IS NULL`; only the writer that changed the row posts the
  line, in the same transaction, so it is posted exactly once whether the creator, the sweep, or both at once close
  it. A poll past `ends_at` reads as closed at once (views compute `closed` from the clock) and refuses votes; the
  sweep (every 30 s, and at boot) writes the close and posts the line.
- **Deleting a poll** (a soft delete) deletes its `polls` row, whose votes cascade; the sweep then never closes it.
- **Limits**: posting uses `send_user` (as messages); votes `poll_vote_user` = 20 at once then 2/s per person.
- **The composer** is a popover anchored to a new composer button (left of the wheel button), built with the wheel
  popover's frame (`popoverStyle`, bg-2 panel, `--line-menu`, `--shadow-3`, `pop-in`), the Settings `input.switch`
  toggles and `Segmented` for Ends in. `/poll` opens it; `/poll Q? a, b` prefills it.
- **The card** borrows QotyVoting's option rows (bar as a `scaleX` fill, count, `VoterStack`) in the accent colour
  rather than the quotes green, inside the message body. "End poll" is a MessageMenu item for the poll's author.
- **The ended line** is a system line with payload `{"type":"poll_ended", …}` → `Message.poll_ended`.

## Review Focus

- Two closes at once (the creator's End poll as the sweep runs): one line. Test: `closing_twice_posts_one_line`.
- A vote after `ends_at` but before the sweep: refused (409), and the view already reads closed. Test:
  `a_due_poll_reads_closed_and_refuses_votes`.
- A held poll overwritten by an event's neutral view (the creator's view vanishing on their own `MessageCreated`).
  Test: `state.test.ts` "MessageCreated keeps a held message's poll".
- A deleted poll: its votes go, votes on it 404, no ended line later. Test: `deleting_a_poll_drops_it_and_its_votes`.
- `/poll` with a question only, or options but no `?`: prefill what there is, never post. Test: `poll.test.ts`.

### Task 1: Protocol, migration and the poll model (server)

**Files:** `protocol/src/rest.rs`, `protocol/src/gateway.rs`, `protocol/src/lib.rs`, `server/migrations/0030_polls.sql`,
`server/src/polls/{mod,routes}.rs`, `server/src/lib.rs`, `server/src/limits.rs`, `server/src/messages/{routes,system}.rs`,
`server/tests/polls.rs`; generated `client/ui/src/lib/protocol/*`.

**Interfaces (produces):**
- `rest::Poll { question, options: Vec<String>, multi, anonymous, ends_at: Option<String>, closed_at: Option<String>,
  closed: bool, voters: u32, mine: Vec<u32>, results: Option<Vec<PollTally>> }`; `PollTally { votes: u32, voters:
  Vec<UserId> }` (empty when anonymous); `PollDuration { Hour, Day, Week, Never }`; `CreatePollRequest { question,
  options, multi, anonymous, ends_in: PollDuration }`; `PollVoteRequest { options: Vec<u32> }`; `PollEnded {
  poll_message_id: MessageId, author_id: Option<UserId>, winners: Vec<String>, votes: u32 }`;
  `rest::poll_limits { QUESTION_CHARS = 200, OPTION_CHARS = 80, MIN_OPTIONS = 2, MAX_OPTIONS = 10 }`.
- `Message.poll: Option<Box<Poll>>`, `Message.poll_ended: Option<Box<PollEnded>>` (skipped when absent).
- `Event::PollChanged { channel_id, message_id }` (channel audience).
- Routes: `POST /channels/{id}/polls` → 201 `Message` (creator view); `GET /messages/{id}/poll` → `Poll`;
  `PUT /messages/{id}/poll/votes` → `Poll`; `POST /messages/{id}/poll/close` → `Poll` (author only, 403 others).
- Migration 0030: `polls (message_id PK → messages CASCADE, channel_id → channels CASCADE, question, options JSON,
  multi, anonymous, ends_at, closed_at, created_at)` + partial index on open polls' `ends_at`; `poll_votes
  (message_id → polls CASCADE, option, voter_id → users CASCADE, voted_at, PK (message_id, voter_id, option))`.
  New tables only.
