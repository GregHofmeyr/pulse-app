# Pinned messages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pin a message in a text channel, DM, group or voice channel's chat for 1 hour, 1 day, 1 week or forever, see it marked, listed in a header popover, announced by a system line, and live for everyone (#178).

**Architecture:** A `pins` table keyed by message; three routes (pin, unpin, list) in a new `server/src/pins` module; two gateway events (`MessagePinned`, `MessageUnpinned`); each loaded message carries its live `pin`, and the pin's system line carries a `pin_line` payload. Expiry is computed on read (expired rows never show) plus a 30 s sweep that deletes them and publishes `MessageUnpinned`. The client adds a message menu (hover bar ⋯ and right-click on the message) with the shared `MenuFlyout`, a marker by the timestamp, the line's rendering, and a header pin button opening a Leaderboard-style popover.

**Tech Stack:** Rust (axum, sqlx/SQLite, ts-rs), Tauri 2 commands, Svelte 5 + vitest.

**Spec:** `docs/superpowers/specs/2026-11-09-pins-design.md`

## Global Constraints

- Where: text, DM, group, voice channels' chats. Not quotes or clips channels.
- Who: anyone who can read and write the chat (send's checks: `channel_for`, plus server membership for server channels).
- Durations exactly: `1 hour`, `1 day`, `1 week`, `Forever`. Menu items: `Pin message ›` / `Unpin message`.
- Cap 50 live pins per chat; refusal text contains "Unpin something first".
- Marker tooltip: `Pinned by alex · 2 days left` / `Pinned by alex`.
- Line: `alex pinned a message for 1 day · See pins` (`…pinned a message` for Forever). Unpins and expiries add no line, no notification.
- Delete removes the pin; edit keeps it.
- Migration 0028, additive only (no rebuild, so no FK guard needed).
- UI: existing tokens, components and classes only; icon sizes 14 inline / 16 buttons / 17-18 header; reduced motion respected.

## Review Focus

- A pin whose time has run out but the sweep hasn't reached: must not show (list, message `pin`, cap count) and re-pinning it must work. Test: `an_expired_pin_is_gone_before_the_sweep`.
- Pinning a system line, a deleted message, or a quote-thread reply: refused 400/404. Test: `system_lines_deleted_messages_and_replies_cannot_be_pinned`.
- A non-member of a server pinning in its channel (channels are readable by all): refused 403, like send. Test in `permissions`.
- Pinning an already-pinned message (two people at once): 409, no second line. Test: `pinning_twice_is_a_conflict`.
- The popover opened in a voice chat panel (narrow column): must fit the column. Covered by CSS `width: min(400px, calc(100% - 24px))` and a render test.

- Routes: `PUT /messages/{id}/pin` (body `PinRequest`, 200 `Pin`), `DELETE /messages/{id}/pin` (204), `GET /channels/{id}/pins` (`Vec<PinnedMessage>`, newest pin first).
- `pins::expire_overdue(s: &AppState, now: &str) -> AppResult<usize>`; `pins::MAX_PINS = 50`; `pins::SWEEP_EVERY = 30 s`.
