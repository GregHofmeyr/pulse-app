# Badges Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The server awards badges (tiered, rare, hidden, first-earner, hand-given) from counters bumped by server
activity; the client shows an unlock toast + sound, a [NEW] state, a trophy case and a 5-badge showcase.

**Architecture:** A new `server/src/badges/` module: `catalogue.rs` (definitions + pure rule evaluation),
`stats.rs` (the `badge_stats` counters, bumped inside the transactions where events already happen), `engine.rs`
(evaluate after commit, write unlocks and first earners, publish `BadgeEarned` to the earner), `time.rs` (pure time
helpers: South African day, 03:00, accompanied voice intervals), `routes.rs` (catalogue, showcase, seen, client
events), `sweep.rs` (Early Adopter), `admin.rs` (the CLI). Profiles carry per-viewer badges (hidden ones masked).
The client core gets the API calls and a muted-talk detector; the Svelte UI gets the trophy case, showcase, toast.

**Tech Stack:** Rust (axum, sqlx/SQLite, clap, ts-rs), Tauri 2 core, Svelte 5 + vitest.

**Spec:** `docs/superpowers/specs/2026-11-03-badges-design.md` (+ owner's picks on issue #49).

## Global Constraints

- Build throttle, every cargo command: `CARGO_BUILD_JOBS=4 flock ~/Projects/pulse-app/target/.cargo-serial nice -n 19 ionice -c3 cargo …`; tests add `-- --test-threads=4`. Never two cargo commands at once. pnpm runs under `nice -n 19` with node from `~/.config/nvm/versions/node/v22.22.3/bin` on PATH.
- Never `pkill -f`, bare `git stash`, `cargo clean`. Commit only on this worktree's branch; never push.
- Public repo: no IPs, secrets, emails, real names; test people are alex/sam/kim/jo. The partner badge stays unnamed.
- Every new protocol field is `#[serde(default)]`. Regenerate bindings with `cargo test -p pulse-protocol export_bindings` and commit them.
- Every UI colour is an `app.css` `:root` token (`client/ui/src/colorTokens.test.ts`); text uses `--*-text` tokens.
- Match surrounding style and comment density. Commits reference `#49` and end with the two attribution lines
  (`Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` / `Claude-Session: https://claude.ai/code/session_015sF1gvj3i81Sm7A5nKY29g`).
- **Never from DM/group activity.** Every hook counts only when the channel has a `server_id`.
- **Counters, not recounts.** Rules read `badge_stats`; nothing recounts `messages`/`voice_sessions`, so a purged channel loses no progress.
- Badges are never taken away by a counter going down (take-backs lower the counter, not the badge).
- Badge bookkeeping never fails the user's request: after-commit checks log a warning on error.
- Time zone: Africa/Johannesburg is fixed UTC+2 (no DST) — a constant offset, no tz database.

## Review Focus

2. **Reaction toggling to farm Reaction Farmer** — add/remove/add by the same person must not net more than 1. Test in Task 4.
3. **A stream that ends and restarts quickly** — closing a stream session must only close the session with the ended stream's `started_at`, never the new one. Test in Task 6.
4. **CLI award while the server runs** — the awarded badge appears with [NEW] (unseen) on the next profile load even though no toast fires. Test in Task 3 (seen = false after award).
5. **Early Adopter with no launch date** — unset config must never award it, sweep or not. Test in Task 6.

**Files:**

**Interfaces:**
- Consumes: Task 1 `evaluate`, `find`, `Def`, `Rarity`.
- Produces:
  - `stats::add(conn: &mut SqliteConnection, user: UserId, key: &str, delta: i64) -> AppResult<i64>` (upsert, floors at 0, returns new value); `stats::set_max(conn, user, key, value) -> AppResult<i64>`; `stats::set(conn, user, key, value) -> AppResult<()>`; `stats::get(conn, user, key) -> AppResult<i64>`; `stats::all(conn, user) -> AppResult<HashMap<String, i64>>`.
  - `engine::check(s: &AppState, user: UserId) -> AppResult<Vec<Badge>>` — one write transaction: read stats + held tiers, `evaluate`, for each raised badge update/insert `user_badges` (tier, `earned_at = now()`, `seen = 0`), `INSERT OR IGNORE` into `badge_firsts` for every newly reached tier, commit, then publish one `Event::BadgeEarned` per raised badge. Returns the raised badges.
  - `engine::after(s: &AppState, users: &[UserId])` — calls `check` for each, logs `tracing::warn!` on error, never returns an error. Every hook calls this after its commit.
  - `engine::grant(db: &SqlitePool, user: UserId, key: &str, tier: u8) -> AppResult<()>` (sets exactly that tier, records firsts for tiers newly reached, `seen = 0`; errors on an unknown key or a tier above `max_tier`) and `engine::revoke(db, user, key, tier: Option<u8>) -> AppResult<()>` (`None` removes the badge; `Some(t)` keeps tiers below `t`, removing the row at 0; also deletes this user's `badge_firsts` rows for removed tiers). Used by the CLI.
  - Protocol (`rest.rs`): `pub enum BadgeRarity { Common, Uncommon, Rare, Epic, Legendary, Mythical }` (snake_case); `Badge` gains `#[serde(default)]` fields `tier: u8`, `rarity: BadgeRarity` (default Common), `first_tiers: Vec<u8>`, `count: u32` (stacking: the stat, else 0), `hidden: bool` (true = masked "???"), `seen: bool` (always true for others' profiles). `first_earner` stays: first at the tier held.
  - Protocol (`gateway.rs`): `Event::BadgeEarned { user_id: UserId, badge: Badge, name: String, icon: String }`, in `only_for`, `channel_id` → None.
